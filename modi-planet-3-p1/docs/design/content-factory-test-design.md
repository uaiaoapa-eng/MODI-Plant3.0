> 비용 모델: [test_cost_model.py](./test_cost_model.py) — 이 실험이 그 가정값을 **실측으로 대체**한다.

## 0. 목적 — 무엇을 검증하고, 무엇을 검증하지 않는가

**검증한다 (이 실험의 범위):** "페르소나 × 성취기준 코드 × modality"로 셀을 분해하고,
**비싼 모델(Opus)로 1회 저술 → 싼 모델(Haiku)로 매턴 서빙(편집)"** 하는 전략이
(a) 커리큘럼에 정합하는 콘텐츠를 만드는가(품질), (b) 매턴 맨바닥 생성보다 싼가(경제성)를
**작은 규모(5~6셀)로 실측**한다. = 상위 설계의 **Phase 0**.

**검증하지 않는다:** RAG 검색 인프라, Redis Stack, ETL, 라이브 수확, 폐루프 측정.
프로덕션 파이프라인은 이 테스트가 GREEN일 때만 착수한다.

## 1. 검증 가설 (합격/불합격이 명확한 형태로)

| ID | 가설 | 반증되면 |
|---|---|---|
| **H1 (분해 타당성)** | 초3~4 수학·과학 성취기준은 `(코드 × modality)` 셀로 손실 없이 분해되고, 각 셀은 독립적으로 저술·서빙 가능하다 | 셀 경계가 겹치거나 한 성취기준이 여러 셀에 흩어지면 → 커버리지 맵 자체가 성립 안 함 |
| **H2 (저술 품질)** | Opus 1회 저술 각본은 교육팀 검수 기준(§5 루브릭)을 **80%+ 통과**한다 | 통과율 낮으면 → 사람 저술 비중↑, 티어링 경제성 약화 |
| **H3 (서빙 수렴)** | Haiku가 원본 각본을 페르소나 문맥으로 **편집**한 결과가, Haiku가 맨바닥 **생성**한 결과보다 품질이 높다 (§6-D "약한 모델은 편집이 쉽다") | 반증되면 → 티어링 전제 붕괴, 그냥 라이브 생성이 맞음 |
| **H4 (경제성)** | 서빙 단가(편집) < 맨바닥 생성 단가. 저술 1회 비용은 예상 서빙 횟수로 amortize된다 | 서빙이 생성보다 비싸면 → RAG/사전제작 전면 보류 (R1 실현) |
| **H5 (다양성)** | 같은 셀 반복 요청 시 산출물이 **유효 범위 내에서 다양**하다(동일 각본 반복률 ≤ 40%). 단 다양화가 성취기준 정합·정답·블록구조를 **해치지 않는다**(불변율 ≥ 95%) | 다양성 없으면 → 동질화·오류전파(R3). 다양성이 정답 훼손하면 → 노브 하향 |

## 2. 테스트 범위 & 셀 정의

**카테고리 축은 edu-agent가 이미 런타임에 태깅하는 값에서 가져온다** (커리큘럼에서 발명 X).
사전제작 콘텐츠의 키 = 라이브 요청의 태그 → 서빙 시 동일 키로 매칭.

- **학년군:** 초3~4 (2022 개정 교육과정 3-4학년군)
- **교과:** 수학, 과학
- **coding_type:** `blockly` **전용** (= 교육과정+MODI 결합 채널) — `orchestrator_stream.py:461` · `tools.py:47`
- **intent:** `implement_request`(각본 서빙) · `question`(개념 설명) · `modify_request`(변형) — `router.py:35-59`
- **성취기준코드:** `[4수03-XX]` 등 (교육과정 축, 신규 통제어휘)
- **modi_module:** `tof·imu·environment·led·motor·speaker·display·...` — `modi_core.md:155` (blockly이므로 항상 지정)
- **셀 PK:** `(coding_type=blockly, intent, 성취기준코드, modi_module)`
- **페르소나 축:** 학년·코딩수준만 생성에 사용. **MBTI·성별은 서빙 톤/다양성 파라미터로만** (셀 PK에 미포함 — §8)

> ⚠ 아래 성취기준 코드/원문은 **대표값(구조 검증용)**이다. 저술 착수 전 교육부 고시
> 제2022-33호 원본과 대조해 확정한다. (파이프라인 1단계 "발명 0, 적재만"에 해당)

### 테스트 셀 매트릭스 — 실데이터 아키타입 기반 (projects/6cd11ca3… 125세션 집계)

> **1차 축 = 프로젝트 아키타입 × modi_modules** (트래픽 근원). 성취기준 코드는 **2차 태그**로 매핑.
> 근거: blockly 44세션 중 자동차 45.5%, 상위 4아키타입 = 77% (Zipf 실측). seed는 기존 세션에서 수확.

| # | 아키타입 | modi_modules | 트래픽 | 매핑 성취기준(2차 태그, 대표) | seed 출처 |
|---|---|---|---|---|---|
| A1 | **자동차/자율주행** | tof+motor+imu | **45.5%** | [4수03] 거리·측정 / 과학 운동·힘 / 조건 | 기존 20세션 → dedup |
| A2 | **LED 색/깜빡** | led | 11.4% | [4수02] 규칙성 / 과학 빛 | 기존 5세션 |
| A3 | **스마트팜/화분** | environment+display | 11.4% | 측정(온·습도) / 과학 식물·환경 / [4수04] 자료 | 기존 5세션 |
| A4 | **전자 주사위/흔들기** | imu+display | 9.1% | [4수04] 자료와 가능성·확률 / 규칙 | 기존 4세션 |
| A5 | 악기/음악상자 | speaker | 6.8% | [4수02] 규칙성 / 과학 소리 | 기존 3세션 |

**저술 대상(1차):** 상위 3아키타입 A1·A2·A3 × 3 intent(implement/question/modify) = **9셀**.
seed는 **기존 세션 수확 우선**($0), 빈 intent(question·modify)만 Opus 자동 저술.

## 3. 테스트 페르소나 (fixtures)

서빙 어댑테이션이 페르소나에 반응하는지 보되, **콘텐츠 본질은 학년·코딩수준만으로 결정**됨을 확인.

```yaml
# tests/fixtures/personas.yaml
- id: p1   # 표준
  grade: 3
  coding: blockly
  mbti: null
  note: "기준선 — MBTI 없이 셀 각본이 그대로 서빙되는가"
- id: p2   # 상위 학년
  grade: 4
  coding: blockly
  note: "같은 성취기준 상위군 — 난이도 상향 편집되는가"
- id: p3   # MBTI 톤 검증
  grade: 3
  coding: blockly
  mbti: "ISTJ"
  note: "p1과 콘텐츠 본질 동일 + 톤만 차이나는가 (본질이 바뀌면 FAIL)"
- id: p4   # 톤 대조군
  grade: 3
  coding: blockly
  mbti: "ENFP"
  note: "p3와 톤은 달라도 성취기준·정답·블록 구조는 동일해야"
```

**핵심 판정:** p1·p3·p4는 **학습 내용·정답·MODI 블록 구조가 동일**하고 오직 설명 톤만
달라야 한다. 셋 사이에 커리큘럼 내용이 갈리면 → "MBTI를 생성 축에 넣으면 안 된다"는
설계 원칙이 실측으로 확인됨(경고 대신 데이터).

## 4. 실행 절차

```
STEP 1  기존 세션 수확 + 아키타입 클러스터링 ($0, 최우선)
  - projects/*/session_*.json 파싱 → blockly 세션 추출
  - 제목·modi_modules로 아키타입 클러스터링 (A1~A5)
  - 클러스터별 최고 품질 1건 선별 → seed_artifact 후보
  - 각 아키타입에 성취기준 코드 2차 태그 매핑
  - 산출: tests/fixtures/archetype_seeds.yaml, curriculum_map.yaml

STEP 2  빈 셀만 Opus 자동 저술 (배치, 사람 개입 0)
  - 수확으로 못 채운 (아키타입 × intent) 셀만 생성
  - 셀 조합 자동 전개: 아키타입 × intent × N시드변형
  - 각 셀 seed_artifact 자동 생성 (Batch API 50%↓, 프롬프트 캐시 최대화)
  - blockly 셀은 modi_core.md 규칙 준수한 Blockly XML + 대표질문 포함
  - 저술 실토큰·실비용 기록 → author_cost_usd

STEP 3  자동 검증 게이트 (사람은 샘플 스팟체크만, H2)
  - (자동) MODI XML 스키마 검증 + 실제 업로드 스모크 테스트  ← 객관, 100% 자동화
  - (자동) 성취기준 정합 LLM-judge (별도 모델) + N시드변형 self-consistency 교차검증
  - (사람) 전수 아님 — 무작위 ~10% 샘플만 §5 루브릭 스팟체크
  - 통과분만 STEP5(저장·인덱스)로. 통과율 = H2 지표

STEP 4  서빙 A/B (H3, H4 핵심)
  - 4 페르소나 × 통과 셀에 대해 두 방식 각각 실행:
      A) 편집:  Haiku(seed_artifact + 페르소나 → 편집)
      B) 생성:  Haiku(성취기준만 주고 맨바닥 생성)   ← 대조군
  - 각 호출의 실토큰·실비용·지연 기록

STEP 5  블라인드 채점
  - 교육팀이 A/B를 라벨 가린 채 루브릭 채점 (H3)
  - MODI XML은 modi_core.md 스키마 자동 검증 + 실제 업로드 스모크 테스트

STEP 6  집계 & 판정
  - §5 지표 산출, §6 게이트에 대입, 비용모델 가정값 교체
```

## 5. 지표 & 채점 루브릭

**콘텐츠 품질 루브릭 (셀당, 각 0~2점, 만점 10):**

| 항목 | 0 | 1 | 2 |
|---|---|---|---|
| 성취기준 정합 | 무관 | 부분 | 정확히 해당 성취기준 |
| 학년 적합성(어휘·난이도) | 부적합 | 애매 | 학년 적정 |
| 사실 정확성 | 오류 有 | 경미 | 정확 |
| MODI 실행성(해당 시) | 업로드 실패 | 경고 有 | 정상 동작 |
| 교육적 구성(도입-활동-정리) | 없음 | 부분 | 완결 |

- **통과 = 8/10 이상 AND 사실정확성·MODI실행성 항목이 각 2점**

**정량 지표:**

| 지표 | 정의 | 출처 |
|---|---|---|
| 저술 통과율 | STEP3 통과 셀 / 9 | H2 |
| 편집 우세율 | A(편집)가 B(생성)보다 고득점인 (페르소나×셀) 비율 | H3 |
| 톤-불변성 | p1·p3·p4 간 **내용 동일** 판정 비율 (톤 제외) | 페르소나 원칙 |
| 서빙 단가(편집) | STEP4-A 실비용 / 호출수 | H4 → 모델 `adapt` 교체 |
| 생성 단가(맨바닥) | STEP4-B 실비용 / 호출수 | H4 → 모델 `gen` 교체 |
| 저술 amortize 손익분기 | `author_cost / (gen − adapt)` = 몇 회 서빙하면 회수되나 | H4 |

## 6. 합격 / 불합격 게이트

| 가설 | GREEN (진행) | RED (보류/폐기) |
|---|---|---|
| H1 | 9셀이 겹침 없이 분해, 각 성취기준 1셀 대응 | 셀 경계 모호 → 좌표축 재설계 |
| H2 | 저술 통과율 **≥ 80%** | < 60% → 저술 프롬프트 개선 후 재시도, 3회 실패 시 사람 저술로 |
| H3 | 편집 우세율 **≥ 70%** AND 톤-불변성 **≥ 90%** | 편집이 생성보다 못하면 → 티어링 폐기, 라이브 생성 유지 |
| H4 | `adapt < gen` AND 손익분기 서빙횟수 ≤ **예상 셀당 서빙수** | 서빙이 더 비싸면 → **RAG/사전제작 전면 보류** (R1) |

**전체 판정:** H1~H4 모두 GREEN → 상위 설계 Phase 1~4 착수 근거 확보.
하나라도 RED → 해당 원인만 격리해 재실험(전면 중단 아님).

## 8. 임베딩 · 다양성 · 크로스유저 재사용 (자동화 폐루프)

**전체는 자동 배치다 — 사람은 STEP3 샘플 스팟체크(~10%)에만 개입.** 1개 셀을 자동 저술해
수많은 학생에게 서빙(amortization) + 서빙은 편집(캐시)이라 맨바닥 생성 대비 저렴 = 비용절감 원천.

**임베딩 (양방향, 같은 공간):**
```
사전제작:  embed(성취기준 + 대표질문 + 각본요약)  → 콘텐츠 벡터 → MySQL 저장 + Redis Stack 인덱스
라이브:    embed(학생 질문 + intent)             → 쿼리 벡터
매칭:      1차 필터(coding_type=blockly, intent) → 2차 벡터 top-k
```

**크로스유저 재사용이 안전한 이유:** 사전제작 콘텐츠는 **학생 PII가 없는 커리큘럼 자산**이므로
타 사용자에게 재사용해도 R5(프라이버시) 무관. (라이브 답변을 수확·재사용하는 방식과 대비되는 강점.)

**편향 방지 다양성 4겹** (다양성은 라이브 생성이 아니라 **여러 사전제작 시드**로 확보 → 비용 불변):

| 겹 | 기법 | 비용 |
|---|---|---|
| A. 시드 다양성 ⭐ | 셀당 각본 N개 변형 자동 저술(같은 성취기준·다른 소재) | 저술만 N배(1회), 서빙 캐시 |
| B. 검색 다양성 | top-k 확률 샘플링(softmax) 또는 MMR | ≈0 |
| C. 서빙 다양성 | Haiku 편집 시 temperature + 페르소나 톤(MBTI의 합법적 자리) | ≈0 |
| D. 공정성 | 예시 이름·소재 중립화, 타 학생 데이터 재사용 금지 | ≈0 |

**불변 제약:** A~C가 변주해도 **성취기준 정합·정답·MODI 블록 구조는 불변**(H5 불변율 ≥95%).
**노브:** `diversity_temperature` — 0=항상 top-1(최대 절감), ↑=시드변형 샘플링(다양성↑, 비용 거의 불변).
