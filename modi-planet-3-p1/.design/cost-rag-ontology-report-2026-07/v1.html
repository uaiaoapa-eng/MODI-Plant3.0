한 줄 결론 — 비용절감의 기술 기반(RAG 폐루프 → 온톨로지 → 재사용 게이트 → 직접서브)은 검증을 거쳐 배포 완료 상태다. 절감은 직접서브 적중 턴부터 즉시 발생하며, 전체 절감률은 적중률에 비례하므로 앞으로의 과제는 기술이 아니라 코퍼스 축적과 적중률 확대다.

1비용절감 근거 — 무엇을 실측했고, 언제 줄어드는가

이슈 #84에서 프로덕션과 동일 경로(CLI 모드)로 3가지 통제 실험을 수행. 동일 요청("파란 하트 좋아요 버튼")으로 재사용 전략별 비용·속도·품질을 격리 비교했다.

1.1 실측 ① — 재사용 전략별 비용·속도·품질 (D3 하네스)

요청 유형 (저장물: "하트 좋아요 버튼")만족도 점수저장물 그대로 제공?

1.3 비용 구조 — 왜 "출력 회피"가 정답인가

  • Langfuse 실측 기준 출력 토큰 비용이 비캐시 입력의 5.6배 — 비용을 지배하는 것은 출력이다. agent/orchestrator_stream.py:65-66
  • 프로덕션은 CLI 구독 모드(USE_LOCAL_CLAUDE=true)로 max_tokens·프롬프트 캐시가 무시됨 → 상한·캐시가 아닌 호출 자체의 회피만이 실효 수단. agent/claude_client.py:24 · agent/prompt_cache.py:8-11

1.4 그래서, 언제 비용이 줄어드는가

시점절감 형태조건
지금 즉시 (2026-07-07 배포 이후) 직접서브 적중 턴마다 생성 토큰 1,199 → 0, 응답도 즉시 반환. near 적중 턴은 출력 −19% 이미 켜져 있음 (DIRECT_SERVE 기본 ON). 단 적중하려면 코퍼스에 유사 저장물이 있어야 함
단기 (수주) — 실트래픽 축적 write-back 폐루프로 코퍼스가 자동으로 두꺼워짐 → 적중률 상승 → 절감률 상승 사용자 트래픽 + near-miss 계측 기반 임계값(TAU) 튜닝 (§6 로드맵 P1)
중기 (1~2개월) — 사전제작 표준 커리큘럼 예제를 미리 생성·등록 → 적중률을 구조적으로 끌어올림 (최대 지렛대) 콘텐츠 팩토리 파일럿 (§6 로드맵 P2)
과금 형태 주의 CLI 구독 모드에서 절감은 청구액이 아니라 세션 리밋(429) 헤드룸 확대 + 응답속도로 나타남. API 모드 전환 시 직접 청구액 절감 + 캐시·상한까지 실효 API 전환은 P1 실측 후 결정 (§6 로드맵 P3)
전체 절감률 추정식 — 코드턴 생성비 기준: 절감률 ≈ 직접서브 적중률 × 95% + near 적중률 × 19%
예) 코드턴의 20%가 직접서브·30%가 near에 적중하면 생성비 약 25% 절감. 교육 도메인은 표준 예제 반복 비중이 높아 적중률 상방이 크다. 실측 절감률은 실트래픽 축적 후 Langfuse 코호트(reuse_tier별 비용)로 확정한다.

4.2 온톨로지가 하는 일 — 검색을 "교육 문맥"으로 확장

  • 구조: 개념 노드(ontology_nodes) + 관계 엣지(ontology_edges: 선수학습·관련·uses). docs/design/rag-db-schema.md:202-210
  • 동작: 요청에서 개념이 잡히면 그래프를 따라 선수학습 경로 → 관련 개념 → 필요한 MODI 모듈 → 학습노트 카드를 모아 생성 프롬프트 앞에 주입(프라임). agent/reuse.py:150-234 (ontology_suggest)
  • 효과: 검색(무엇이 비슷한가)에 교육 관계(무엇을 먼저 알아야 하는가)를 더해, 생성물이 학습 맥락에 맞게 나온다. 정확성 축과 비용 축이 같은 인프라를 공유하는 구조.
  • 배포 정합: 메인 앱에는 torch가 없어 벡터 검색이 불가하므로, 그래프·게이트 조회를 rag-search(:8100)로 프록시하고 실패 시 로컬 폴백. PR76에서 정합 완료. agent/reuse.py:81-147
